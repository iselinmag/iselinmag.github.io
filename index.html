Challenges & what I learned

Two technical problems, the choices I made and why.

Campus Lost & Found API

Releasing a new version without taking the API down

Problem
A normal redeploy stops the running container, so every request during the restart fails.
What I chose
Two containers, blue and green, behind NGINX. The pipeline deploys to the idle one, waits for its health check and runs a k6 load test against it. Only then does a script point NGINX at it and reload.
Why
The live version keeps serving traffic the whole time. The script validates the new NGINX config first and restores the old one if it fails, and the old container stays up as a fallback. While switching, a client sent requests nonstop, and every one returned HTTP 200.

TourPlanner

Searching for values that are not in the database

Problem
Tours have a popularity and a child-friendliness rating, worked out from the logs each time. Since they are never stored, a database query can't search them, so searching for "child-friendly" found nothing.
What I chose
Search in two passes. First a JPQL query over stored fields and log comments, then a filter in the service layer over the computed labels, merging the results without duplicates.
Why
Storing the values would mean keeping them in sync every time a log changes. Computing them on request keeps one source of truth, at the cost of a little more work per search.

Up next · Spring 2027

Bachelor thesis with Omda

AI speech-to-text and real-time documentation for out-of-hours emergency call centres.

Operators at emergency call centres have to listen, assess and write notes at the same time, often under heavy pressure. Our team of four will test Norwegian speech-to-text models that can run locally, since patient calls cannot be processed in the cloud. The goal is a prototype that fills in the fields of the operator's checklist as the call goes on, so the operator only confirms or corrects.

  • Evaluate local speech-to-text models on simulated calls with dialects and medical terms
  • Structure the text in real time instead of writing a summary afterwards
  • Design how the operator works with AI-generated text during the call
  • My background as a dental health secretary helps with medical terms and documentation under time pressure
